# The build tools scripts\source-wheel.py builds a wheel with, installed with
# --require-hashes into a throwaway environment and used with
# --no-build-isolation, so a build requirement cannot float to whatever the
# index serves that day. The set covers both packages the Windows build makes
# from source: triangle builds with Cython and setuptools, and tetgen with
# scikit-build-core, nanobind, CMake and Ninja. The versions are those that
# satisfied every package's build-system requirements on 2026-09-15, and each hash
# is the sha256 PyPI publishes for that file.
#
# EVERY ARCHITECTURE AND INTERPRETER THE SCRIPT RUNS FOR HAS ITS FILE LISTED.
# pip picks the one wheel that matches the interpreter and checks it against this
# list, so a missing platform is a hash failure rather than a fall back to an
# sdist: ARM64 runs python-build-standalone 3.12, and x64 is exercised with the
# NuGet CPython 3.11 build.bat links PyO3 against. exceptiongroup, tomli and
# typing-extensions are scikit-build-core's dependencies below Python 3.11 only;
# they are listed for the 3.11 interpreter and pip skips them on 3.12.
#
# To move a pin, take the version and every file hash from
# https://pypi.org/pypi/<name>/<version>/json together, and rebuild both wheels
# with scripts\source-wheel.py before committing.
